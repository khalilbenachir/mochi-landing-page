# Landing Architecture and SEO Implementation Plans

Generated by the `improve` skill on 2026-11-08 at commit `0fa9683`.

These plans implement the requested direction: Tailwind utility classes remain in
`className`; CSS Modules and hand-written class selectors are removed; reusable colors,
shadows, radii, motion, and breakpoints move into the Tailwind theme; the active landing
page becomes a feature boundary; and unreachable code and media are removed safely.

The SEO planning pass was added by the `improve` skill on 2026-11-08 at commit
`cd31005`. Plans 008-012 make the production origin fail-safe, correct the web-manifest
icons, remove false sitemap freshness, add a branded social card, and enforce the full
localized crawler contract over HTTP.

The localized 404 planning pass was added by the `improve` skill on 2026-11-09 at
commit `03101c3`. Plan 013 adds a real localized catch-all 404, keeps landing-only
metadata and structured data on the home route, and reuses the existing Mochi shell
and wondering mascot without introducing another generated asset.

Execute in order. Each executor must read its plan fully, run every verification gate,
honor every STOP condition, and update its status row here when done.

## Findings represented by these plans

- The only page route imports `MaquetteLanding`; `components/sections`,
  `features/change-reminder`, and `lib/change-timer` are disconnected from it.
- The active landing uses ten CSS Modules totaling about 1,239 lines. The repository has
  about 2,274 CSS Module lines overall, including about 1,035 lines in the disconnected
  legacy implementation.
- `MaquetteLanding.module.css` is imported by live code but most of its 205 lines are
  unused; only the account composition, root wrapper, and mobile menu remain reachable.
- The active CSS and TSX contain many literal colors and local palette aliases despite a
  partial Tailwind `@theme` in `src/app/globals.css`.
- Forty-two tracked legacy media files total 2,180,975 bytes. Eighteen untracked poster,
  reference, and composite images total 1,956,888 bytes and have no runtime consumer.
- The current working tree contains unstaged edits in many deletion candidates. Plan 002
  must not proceed until those edits are preserved or explicitly approved for discard.

### SEO findings represented by plans 008-012

- A production build without `NEXT_PUBLIC_SITE_URL` succeeds while sitemap and JSON-LD
  use `http://localhost:3000`; canonical and robots sitemap signals are omitted.
- The current suite does not assert canonical links, `hreflang`, Open Graph/Twitter
  metadata, JSON-LD, robots, sitemap, manifest, or crawler-facing image endpoints.
- `src/app/manifest.ts` declares the 256×256 WebP app icon as 512×512.
- Localized pages have no deterministic Open Graph or Twitter preview image.
- `src/app/sitemap.ts` publishes the build clock as `lastModified` for every locale.

### 404 direction represented by plan 013

- Unknown navigational URLs currently render Next.js's generic `/_not-found` UI.
- A localized not-found route needs an explicit `[...rest]` page that calls
  `notFound()`; rendering a styled component directly would incorrectly return 200.
- Landing metadata and `MobileApplication` / `FAQPage` JSON-LD currently live in the
  locale layout, so adding another localized page would make those signals leak onto
  the error document unless they move to the home route.
- The existing 460×368 wondering Mochi face already matches the requested 404 concept;
  generating a second mascot asset would add brand and asset-manifest risk without a
  material visual benefit.

## Findings considered and rejected

- **Replace poster geometry with ordinary flow layout:** rejected because the coordinate
  system is intentional and visually load-bearing. The plans preserve it with Tailwind
  arbitrary-value utilities and small typed primitives.
- **Use generated/dynamic Tailwind class names:** rejected because Tailwind cannot
  reliably discover them. Variant maps must contain complete static class strings.
- **Delete all of `components/ui`:** rejected because the active landing still uses the
  shadcn-compatible `Button`, and the design-system boundary should remain available.
- **Treat every literal asset path as the full live set:** rejected because flavor and
  mood paths are generated from typed IDs. Plan 002 creates an explicit runtime asset
  manifest before deletion.
- **Remove every CSS rule, including Tailwind's theme/base entry point:** rejected as
  incompatible with Tailwind 4 and shadcn. The target is no CSS Modules or custom class
  selectors; `globals.css` remains the Tailwind import, theme, and minimal base layer.
- **Delete untracked reference art without a provenance check:** rejected because those
  files may be informal design sources even though they are not runtime assets.

- **Shared `DecorativeRays` / `HeartIcon` primitives (plan 003 refresh):** rejected. Each
  section's rays use different hand-placed path geometry (only Comparison and Plans
  match) and already use `currentColor`; a shared component would move section art into
  `shared/` behind a variant switch. `PosterStage` and `AppStoreBadge` moved to plan 004,
  where their consumers are migrated.
- **Merging near-identical token values (plan 003):** rejected by design. Six values are
  declared under two role names (e.g. `#ef4a7a` as `cycle-period` and `brand-coral`);
  the dead/undefined-token tests keep the vocabulary exact.
- **Replace the existing browser and Apple icons:** rejected. The 64×64 favicon and
  180×180 Apple touch icon are valid; plan 009 fixes only the mismatched install manifest.
- **Enumerate individual AI crawlers in `robots.txt`:** rejected. The current wildcard
  allow policy already covers crawlers that honor robots rules, while a vendor list would
  drift and still could not guarantee crawling or indexing.
- **Treat `llms.txt` as mandatory SEO infrastructure:** rejected for this pass. It is an
  optional convention, and a hand-maintained copy would violate the repository's rule
  against agent-only facts that can drift from visible localized content.
- **Consolidate every locale's JSON-LD entity IDs in this pass:** deferred. The current
  graph is valid and no observed defect requires a schema-model migration; revisit after
  the real App Store URL and production identity are available.

## Audit boundaries

This was a focused architecture audit of the landing composition, Tailwind/shadcn usage,
next-intl integration, dead source, dependencies, tests, and public media. It was not a
content strategy, analytics, legal/medical-copy, or full application-security audit.

The 2026-11-08 SEO pass covered repository-controlled metadata, localized canonical and
alternate signals, JSON-LD, robots, sitemap, manifest/icon assets, social previews, and
testability. It did not cover a live domain, CDN/WAF bot policy, DNS, Search Console,
backlinks, indexing/rank outcomes, external preview caches, or a full content strategy.

The 2026-11-09 404 pass covered navigational unknown routes matched by the existing
locale middleware, localized recovery copy, route-specific metadata ownership, shell
reuse, responsive composition, accessibility, and visual/e2e verification. It did not
cover missing static assets or other dot-containing paths excluded by middleware, the
experimental global-not-found convention, runtime exception pages, legal/help routes,
or a redesign of the landing page.
